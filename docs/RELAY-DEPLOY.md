# הפעלת שרת הממסר והרישוי — מדריך צעד אחר צעד

השרת הוא "תיבת דואר" מוצפנת: דרכו עוברים רישיונות, עדכוני סטטוס והודעות הצ'אט.
הוא **לא יכול לקרוא את ההודעות ולא לזייף רישיון** — הכול מוצפן וחתום במפתחות שאינם עליו (ראו `LICENSING-DESIGN.md`).

## מה צריך
- שרת וירטואלי (VPS) עם **Ubuntu 24.04** (או 22.04), 1GB זיכרון מספיקים. גישת SSH כ-root.
- **דומיין** (או תת-דומיין, למשל `relay.example.co.il`).
- המחשב שלך עם SuperSuite מותקנת.

## שלב 1 — הדומיין
אצל ספק הדומיין: רשומת **A** לתת-הדומיין, שמצביעה לכתובת ה-IP של השרת. ייתכן שייקח עד שעה עד שזה יתעדכן.

## שלב 2 — העלאת השרת והתקנה
במחשב שלך, בתיקיית הפרויקט:
```bash
node tools/pack-relay.js
```
נוצר הקובץ `dist/supersuite-relay.tar.gz`. מעלים ומתקינים:
```bash
scp dist/supersuite-relay.tar.gz root@<כתובת-השרת>:/root/
ssh root@<כתובת-השרת>
tar -xzf supersuite-relay.tar.gz && cd supersuite-relay
bash server/deploy/install.sh relay.example.co.il
```
הסקריפט מתקין Node.js, שירות שעולה לבד אחרי הפעלה מחדש, **HTTPS אוטומטי** (Caddy + Let's Encrypt, כולל חידוש), וחומת אש.
בסוף: לפתוח בדפדפן `https://relay.example.co.il/health` — צריך להופיע `"ok":true`.

**עדכון גרסה:** אותם צעדים שוב. הנתונים (`/var/lib/supersuite-relay`) נשמרים.
**יומן:** `journalctl -u supersuite-relay -f`

### דרך מהירה: Google Cloud (במקום שלבים 1–2)
לגוגל יש שרת קטן (e2-micro) שנשאר חינמי גם אחרי תקופת הניסיון — באזורים בארה"ב בלבד. התנאים משתנים; כדאי לבדוק באתר.
1. **פעם אחת, בעצמך:** חשבון ב-console.cloud.google.com, פרויקט חדש, והפעלת חיוב (כרטיס אשראי נדרש גם למסלול החינמי).
   מומלץ: **Billing ← Budgets & alerts** — התראה על דולר אחד.
2. התקנת gcloud (https://cloud.google.com/sdk/docs/install) ו-`gcloud auth login` (נפתח דפדפן לכניסה).
3. פקודה אחת — יוצרת את השרת, כתובת קבועה, פורטים, ומתקינה הכול:
   ```bash
   bash server/deploy/gcp-create.sh <project-id> relay.example.co.il
   ```
4. בסוף מוצגת כתובת ה-IP — רשומת **A** אצל ספק הדומיין. תעודת ה-HTTPS נוצרת לבד אחרי שה-DNS מתעדכן.

**עדכון גרסה:** אותה פקודה שוב — השרת הקיים מתעדכן, הנתונים נשמרים.
**עלות צפויה:** 0 עד כ-3 דולר לחודש (ייתכן חיוב על כתובת ה-IP). דיסק — Standard בלבד (SSD אינו בחינם).

## שלב 3 — NetFree
מחשבים מסוננים חוסמים דומיין שלא אושר. יש לבקש מ-NetFree לפתוח את הדומיין של השרת —
**גם אצלך וגם אצל כל לקוח** (או לבקש פתיחה כללית לדומיין, כשירות לתוכנה).

## שלב 4 — מפתח מנהל-העל (אצלך בלבד)
1. בתוכנה: **רישוי ומערכות ← 🔑 הגדרת מצב מנהל-העל**. בוחרים סיסמה חזקה.
   **הסיסמה לא ניתנת לשחזור** — בלעדיה אי אפשר להנפיק, להשבית או לחדש רישיונות. לשמור במקום בטוח.
2. **שמירת המפתח הציבורי לקובץ** — הקובץ הזה (ציבורי, לא סודי) נכנס לתוכנה: `shell/licensing/root-keys.js`.
3. גיבוי: התיקייה `%APPDATA%\super-suite\owner` מכילה את המפתח הפרטי, מוצפן בסיסמה. לגבות אותה לכונן חיצוני.

## שלב 5 — גרסה עם רישוי, ורישיון לך
⚠ **מהרגע שהמפתח בתוכנה, כל התקנה בלי רישיון ננעלת** (הנתונים לא נמחקים — רק הגישה).
לכן הסדר חשוב:
1. מכניסים את המפתח ל-`root-keys.js` ובונים מתקין (`npm run dist:local`).
2. **לפני** שמתקינים אותו: בגרסה הנוכחית — **רישוי ומערכות ← עבודה מרחוק**, מגדירים את כתובת השרת.
3. מתקינים את הגרסה החדשה. המערכת שלך תבקש רישיון: "בקשת רישיון", ובמצב מנהל-העל — "בדיקת בקשות חדשות" ← הנפקה.
4. מעכשיו — **הודעות** עובדות מול כל לקוח שקיבל ממך רישיון.

## מה יש בשרת, ומה לא
- יש: תיבות מוצפנות, מפתחות ציבוריים זמניים, ומטא-נתונים (מי שלח למי ומתי, וגודל).
- אין: תוכן הודעות, סיסמאות, מפתחות פרטיים, נתוני הנהלת חשבונות.
- הודעה נמחקת מהשרת ברגע שהנמען קיבל אותה. הודעה שלא נאספה 60 יום נמחקת (הרשמות ששולמו — לא נמחקות).
- הגנה מהצפה (בדיקת האבטחה 21.10.2026): מכתובת אחת — עד 1,000 הודעות בשעה, 20 דפי תשלום ביום ו-3 הרשמות לתכנית חינם ביום.
  כל הנתונים בשרת יחד — עד 2GB; מעבר לזה שליחה רגילה נדחית, ו-256MB נשמרים להרשמות ששולמו. דיסק השרת (30GB) לא מתמלא.
- קובץ בשרת שלא נקרא (פגום, תקלת דיסק) — השרת עונה "לא זמין כרגע" ולא דורס אותו. אם זה קורה — לבדוק ביומן (`journalctl -u supersuite-relay`) איזה קובץ.
