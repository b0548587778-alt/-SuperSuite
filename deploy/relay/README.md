# הפעלת שרת הרישוי באינטרנט

השרת (`server/license-relay.js`) הוא תיבת דואר בין המערכות. דרכו עוברים בקשות רישיון, אישורים, עדכוני סטטוס, הודעות ועדכוני גרסה.
הוא לא מנפיק רישיונות ולא מחזיק מפתחות פרטיים, כי כל התוכן חתום ומוצפן במחשבים עצמם. לכן גם אם מישהו פורץ לשרת, הוא לא יכול לזייף רישיון או לקרוא הודעות.

בלי שרת התוכנה ממשיכה לעבוד כרגיל, והעברת קבצים ידנית נשארת זמינה.

## מה צריך

| מה | למה | הערות |
|---|---|---|
| **שרת וירטואלי (VPS)** | מחשב שפועל כל הזמן ויש לו כתובת IP קבועה | Linux (Ubuntu 24.04), ‏1 vCPU ו-1GB זיכרון מספיקים. אפשר לבחור בכל ספק, כולל ספקים עם שרתים בישראל |
| **דומיין** | כתובת קבועה שהתוכנה מתחברת אליה, למשל `relay.example.co.il` | אפשר להשתמש בתת-דומיין של דומיין שכבר יש לך. מגדירים **רשומת A** שמפנה לכתובת ה-IP של השרת |
| **HTTPS** | התוכנה מסרבת להתחבר לכתובת שאינה `https://` | **Caddy** מנפיק את התעודה ומחדש אותה לבד (Let's Encrypt), בלי עלות ובלי פעולה ידנית |
| **פורטים 80 ו-443 פתוחים** | 443 לחיבורים, ו-80 לאימות התעודה | בחומת האש של הספק |
| **אישור הדומיין בסינון** | במחשבים מסוננים (NetFree ואחרים) דומיין חדש נחסם | פונים לספק הסינון ומבקשים לאשר את הדומיין, ומציינים שזה שרת API של תוכנה ולא אתר גלישה |

## התקנה עם Docker (מומלץ)

על השרת, אחרי שהדומיין כבר מפנה אליו:

```bash
# 1. Docker
curl -fsSL https://get.docker.com | sh

# 2. הקוד (או העתקה בדרך אחרת, למשל scp)
git clone https://github.com/b0548587778-alt/-SuperSuite.git supersuite
cd supersuite

# 3. הדומיין
cp deploy/relay/.env.example deploy/relay/.env
nano deploy/relay/.env        # RELAY_DOMAIN=relay.example.co.il

# 4. הפעלה
docker compose -f deploy/relay/docker-compose.yml up -d --build
```

בדיקה מכל מחשב:

```bash
curl https://relay.example.co.il/health
```

אם השרת תקין, התשובה היא `{"ok":true,"service":"supersuite-license-relay"}`.

**עדכון גרסה:** מריצים `git pull` ואז שוב את פקודה 4. התיבות נשמרות בכרך `relay-data` ולא נמחקות בעדכון.
**לוגים:** `docker compose -f deploy/relay/docker-compose.yml logs -f`

## התקנה בלי Docker

1. מתקינים Node.js 22 ואת Caddy (`apt install caddy`).
2. מעתיקים את הפרויקט ל-`/opt/supersuite-relay`. השרת צריך רק את `server/`, `shell/licensing/` ו-`modules/econ/core/israeliId.js`.
3. מתקינים את השירות: `deploy/relay/supersuite-relay.service` (ההוראות בראש הקובץ).
4. מעתיקים את `deploy/relay/Caddyfile` ל-`/etc/caddy/Caddyfile`, מחליפים את `{$RELAY_DOMAIN}` בדומיין ואת `{$RELAY_HOST:relay}` ב-`127.0.0.1`, ואז מריצים `systemctl reload caddy`.

## חיבור התוכנה

בכל מחשב: **מערכת כלכלית ← 🔑 רישוי ומערכות ← 🌐 עבודה מרחוק ← שרת רישוי**. מזינים `https://relay.example.co.il` ולוחצים "סנכרון עכשיו".

## מה לא מופעל בהגדרות האלה

- **הרשמה ותשלום** (`--root-pub` / `--pay`) כבויים. ספק הבדיקות (`--pay test`) מסרב לפעול עם דומיין אמיתי, וזה מכוון.
- **תשלום אמיתי — Cardcom:** `--root-pub owner.pub.json --pay cardcom --public-url https://<הדומיין>`, ובמשתני הסביבה של השירות:
  `SS_CARDCOM_TERMINAL` (מספר המסוף) ו-`SS_CARDCOM_API_NAME` (שם ה-API, מממשק הניהול של Cardcom). **אין לשמור אותם בקבצי הפרויקט.**
  Cardcom מפיקה חשבונית מס-קבלה ללקוח. ה-webhook שלה אינו חתום — השרת מאמת כל תשלום בפנייה חוזרת ל-Cardcom (`GetLpResult`).
  לפני הפעלה ללקוחות: עסקת בדיקה אחת בסכום קטן, וביטול שלה בממשק של Cardcom.
- **הרישוי במחשבים** עדיין כבוי (`root-keys.js` ריק). השרת יעבור הודעות, אבל אכיפת רישיונות תתחיל רק כשיופעל הרישוי.

## גיבוי

התיבות הן הודעות שממתינות לאיסוף. אחרי שהמחשב קולט אותן, הן כבר שמורות אצלו. אובדן השרת לא מוחק נתונים מהמחשבים, רק הודעות שעדיין לא נאספו. אפשר לגבות את הכרך `relay-data` מדי פעם, אבל זה לא הכרחי.
